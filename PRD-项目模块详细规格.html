3.4 层级选择器
属性 值
功能说明 在项目多层级结构中切换查看（项目部 → 工作组 → 施工组）
显示内容 层级图标 + 层级名称 + 层级类型标签（项目部 / 工作组 / 施工组）+ 面包屑导航
面包屑 显示完整路径，如：项目部 › 水电工作组
切换方式 点击下拉，显示所有可选层级；每个选项含层级类型与概要信息（如「4 个工作组 · 8 份合同」），当前层级带勾选标记
切换后 更新面包屑导航，触发局部刷新（200ms 延迟 + loading 动画），显示对应层级的合同 / 任务 / 待办数据
层级选择器下方区域数据统计口径

层级选择器下方的合同概览 / 任务统计 / 待办事项区域数据，均按当前所选架构层级及其隶属子层级聚合统计，而非全局项目数据；切换层级即切换统计范围（与 §3.5 数量统计来源说明一致）。

隶属关联关系：每份合同、每个任务包 / 任务项均通过 belong_level_id 归属到某一施工组（或工作组）；施工组归属到工作组，工作组归属到项目部，形成「项目部 › 工作组 › 施工组」三级树。

关联关系计算示例：

  • 选中「项目部」：统计 = 项目部自身 + 其下全部工作组 + 全部施工组 的合同 / 任务 / 待办之和（最全）。
  • 选中「水电工作组」：统计 = 该工作组自身 + 其下全部施工组（如强电施工组、弱电施工组）之和，不含其他工作组。
  • 选中「强电施工组」：统计 = 仅该施工组自身 的合同 / 任务 / 待办，不含上级工作组及其他施工组。

聚合规则：沿 belong_level_id 向上追溯到所选层级即计入；不归属该层级树的合同 / 任务不计入。

3.13 已完成状态 - 状态流转与回退规则

核心原则：项目进入“已完成”状态后，不锁定任何原有功能，入口与权限与“进行中”状态保持一致。用户仍可继续对合同发起变更、创建架构（添加工作组 / 施工组）、创建合同等操作。仅在满足特定触发条件时，项目状态才回退为“进行中”，并在全部任务再次完成后自动恢复为“已完成”。

状态流转：

┌──────────┐ │ 已完成 │ └────┬─────┘ │ ① 发起合同变更 │ ② 创建新合同（创建架构本身不单独触发） ▼ ┌──────────┐ │ 进行中 │ └────┬─────┘ │ 全部任务再次完成（口径同 §3.5） ▼ ┌──────────┐ │ 已完成 │ ← 判定逻辑与首次进入一致 └──────────┘

回退触发条件：

触发动作 说明 状态变化
发起合同变更 对任意已签约合同发起变更流程，提交成功（合同进入变更中 / 变更确认中等变更态） 已完成 → 进行中
创建新合同 在工作组节点创建新合同并提交成功（合同进入拟定中等），详见 §6.6 创建合同功能 已完成 → 进行中
创建架构 仍支持操作（添加工作组 / 施工组）；本身不单独触发回退，但其下层级后续若创建新合同，按“创建新合同”规则回退 不单独回退

回退后的表现：

  • 顶部状态标签由绿色“已完成”变为蓝色“进行中”。
  • 页面恢复“进行中”态布局与交互（§3.1–§3.9）：快捷导航、待办事项、今日动态等重新激活；已完成态专属收敛（如无待办项、收缩态展示）解除。
  • 进度 / 任务统计按 §3.5 数量统计规则 重新计算——因新增变更任务或新合同任务，总任务数 / 已完成数相应变化。

再次完成：

  • 当项目内全部任务再次达到“已完成”（已完成任务数 = 已签约合同内有效总任务数，口径同 §3.5），系统自动将项目状态由“进行中”更新回“已完成”。
  • 该判定逻辑与项目首次进入“已完成”完全一致，不另设特殊规则。

状态一致性：项目状态为全局字段（projects.status），服务方发起的回退 / 再次完成，业主端（见 §12.11）同步呈现，两端状态标签与布局随状态联动，无需各自维护。

7.6 邀请身份区分与默认权限规格

邀请成员时，需先明确被邀请人的身份，不同身份对应不同的字段填写、落地终端小程序、项目内默认权限。邀请弹窗顶部以分段控件 invite-category 提供两类选择：

身份分段 显示字段 落地终端 项目内默认权限
服务人员 邀请到架构层（选择所属工作组 / 角色，同原逻辑） 🛠️ 服务端小程序 仅基础公开数据，无治理权限（permission_level=basic）
业主 / 业主家人 隐藏"邀请到架构层"；直接纳入项目，不选择架构层与角色 🏠 业主端小程序（仅查看 / 确认，不进入施工组） 全部权限（permission_level=full）

默认权限规则

  • 服务人员被邀请到项目后默认权限为 basic：仅可查看项目基础公开数据（项目基本信息、公开进度等），无治理权限（不可增删改成员、架构、资金、合同等）。
  • 业主 / 业主家人被邀请进项目后默认权限为 full：拥有项目全部权限。
  • 项目第一人（创建者 / 发起业主）固定为 full 且为项目治理权人，不受上述默认规则约束。
  • 默认权限由 member_category 推导，落库于 project_members.permission_level；邀请记录侧的预期权限落库于 invite_records.target_permission。

交互规则

  • 身份分段默认：弹窗打开时默认选中"服务人员"；每次打开弹窗重置为默认状态。
  • 字段联动：选择"服务人员"时显示"邀请到架构层"表单；选择"业主 / 业主家人"时隐藏该表单。
  • 邀请方式：平台内选择 / 二维码 / 微信好友三种方式在两类身份下均保留；二维码提示文案随身份变化（服务人员："扫码加入工作组"；业主及家人："扫码进入业主端小程序"）。
  • 落地端提示：弹窗底部以 invite-target-app 实时提示"被邀请人将进入 服务端小程序 / 业主端小程序"，并展示该身份对应的默认权限（服务人员："仅基础公开数据，无治理权限"；业主及家人："全部权限"），避免误邀。
  • 平台内选择匹配标准：选择"服务人员"身份时，平台内候选列表仅包含已认证至少一个角色的服务方人员，未认证任何角色者不进入候选列表（不在可供搜索的人员内展示）；选择"业主 / 业主家人"时不受此限，业主及家人均可被选择。该标准仅在"服务人员"身份下生效。

被邀请人接收与处理邀请

  • 平台内选择：邀请人在平台内选定目标用户并确认后，被邀请人登录对应小程序，在"消息 / 待处理"中看到邀请，点击接受即正式加入并获对应默认权限；点击拒绝则邀请作废。
  • 二维码邀请：被邀请人扫码后进入小程序，自动跳转项目详情页并弹出加入确认；确认后按所选身份与架构层加入，获对应默认权限；二维码 7 天有效，过期提示"邀请已失效"。
  • 微信好友：被邀请人收到邀请卡片，点击进入小程序，流程同二维码——弹出加入确认，确认后加入并获默认权限。
  • 权限生效：无论哪种方式，被邀请人接受后默认权限立即按 member_category 推导生效（服务人员=basic，业主及家人=full）；后续可由具备治理权限的成员在权限设置中调整。
  • 接收侧交互：接受成功 轻提示"已加入项目"；拒绝 / 失效时 轻提示"邀请已失效 / 已拒绝"；业主端被邀请人接受后仅可见项目公开信息与本人相关数据，不进入施工组。

与数据模型的对应

  • project_members.member_category：枚举 service / owner，决定成员进入哪端小程序（必填，默认 service）。
  • project_members.permission_level：枚举 basic / full，成员默认权限等级，由 member_category 推导（必填）。
  • invite_records.target_category：枚举 service / owner，service 时填写 target_role、owner 时 target_role 置空。
  • invite_records.target_permission：枚举 basic / full，被邀请人接受后将获得的默认权限，由 target_category 推导。
  • users.certified_role_count：已认证服务角色数量；平台内选择邀请"服务人员"时，仅 certified_role_count >= 1 的人员进入候选池，未认证者不可被匹配。
  • 业主及家人不进入施工组，其账户 user_type 仍为 owner，仅通过 member_category=owner 与默认 permission_level=full 体现。
说明

业主端小程序（owner-miniapp）邀请弹窗同样提供该身份分段，逻辑与服务端一致；当邀请人为业主本人时，选择"业主 / 业主家人"即可将家人纳入项目。三端（PC 管理端、服务方小程序、业主小程序）邀请落库字段保持一致。

默认展开规则（核心需求）

仅展开包含进行中任务的阶段，其余阶段默认收起。具体规则：

  1. 打开抽屉时，status = in_progress 的阶段默认展开（collapsed = false），其余阶段（completed / pending）默认收起（collapsed = true）。
  2. 展开后自动调用 scrollToCurrentTask()，将首个 in_progress 任务滚动至内容区中央并高亮（文字 #D46B08 + 加粗）。
  3. 若不存在进行中任务（全部完成或全部待开始），默认展开首个阶段，不触发定位滚动。
  4. 用户手动展开/收起后，状态保持至抽屉关闭；重新打开抽屉时恢复默认展开规则。
